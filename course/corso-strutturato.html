Modulo 1

Come funziona Claude

Obiettivo: scegliere il modello giusto per un compito e riconoscere i limiti del sistema.

Concetto

Claude genera risposte a partire da ciò che vede nella conversazione. Non consulta un database e non ricorda ciò che non gli avete dato.

  • È molto bravo con testo, struttura, ragionamento e codice.
  • Può sbagliare fatti, numeri e citazioni, e lo fa con sicurezza.
  • La qualità dipende dal contesto che fornite.
Effort, contesto, verifica
  • Effort: più ragionamento, risposte più accurate su problemi complessi, ma più lente.
  • Finestra di contesto: in una chat molto lunga le informazioni iniziali perdono peso.
  • Verifica: ogni fatto, numero o citazione va controllato sulla fonte.
ModelloQuando usarloEsempio
HaikuCompiti semplici e ripetitivi, in volumeCorreggere 50 descrizioni prodotto
SonnetLavoro quotidiano: il default consigliatoScrivere un post, riassumere un verbale
OpusRagionamenti complessi, lavori delicatiAnalizzare una strategia o un contratto

Esercizio: eseguite un compito della vostra settimana con due modelli diversi. Annotate differenza di qualità e tempo.

Modulo 2

Il metodo BRIEF: sei parti per un buon prompt

Obiettivo: scrivere un prompt che produce un risultato utilizzabile al primo o al secondo tentativo.

LetteraParteDomanda guidaEsempio
BBackgroundQual è il contesto?“UX Boutique offre audit di usabilità per e-commerce medi.”
RRuoloChi risponde, con quale competenza?“Sei un copywriter senior, tono sobrio.”
IIntentoCosa deve ottenere chi legge?“Far richiedere un audit gratuito.”
EEsempiCome deve essere il risultato?“Tono come in questo esempio: …”
FFormatoLunghezza, struttura, cosa escludere?“120 parole, due hashtag, niente emoji.”
+VerificaCome controllo il risultato?“Elenca le affermazioni contestabili.”

  1. Scrivete le sei parti

    Anche in forma breve. Un compito semplice ne richiede due o tre.

  2. Leggete l’output

    Annotate cosa manca rispetto a ciò che vi aspettavate.

  3. Correggete una cosa per volta

    “Il titolo è generico: proponi tre alternative con un numero.”

Modulo 2 · Esempio completo

Lo stesso compito, scritto in due modi

Prima 
Scrivi un post Instagram sul nostro
servizio di audit.

Claude decide da solo pubblico, tono, lunghezza e formato.

Dopo 
Background: UX Boutique offre audit di
usabilità per e-commerce medi. Pubblico:
responsabili marketing, non designer.
Ruolo: copywriter senior, tono sobrio.
Intento: far richiedere l'audit gratuito.
Esempio di tono: "Il checkout perde utenti?
Di solito il problema è in tre passaggi."
Formato: max 120 parole, due hashtag,
nessuna emoji, chiusura con l'invito.
Verifica: elenca le affermazioni che un
cliente potrebbe contestare.
Tecniche utili
  • Tag XML per separare istruzioni e materiali: <istruzioni> e <testo>.
  • Few-shot: due o tre esempi valgono più di una descrizione lunga.
  • Prompt a catena: estrai i fatti, scrivi la bozza, rivedi con i criteri.
  • Autocritica: “Rileggi la bozza rispetto ai criteri e segnala cosa non rispetta.”
Errori comuni
  • Descrivere il compito ma non il pubblico.
  • Chiedere “un tono professionale” senza esempio.
  • Cambiare tre cose insieme nella revisione.
  • Non dire cosa escludere.

Modulo 3

Projects: istruzioni e documenti sempre presenti

Obiettivo: un Project che rende Claude coerente con il vostro lavoro senza ripetere il contesto. Prerequisiti: almeno due documenti di riferimento approvati.

Come si imposta

  1. Barra laterale → Projects → Nuovo Project. ⚠ da verificare

  2. Nome preciso: “UX Boutique — Brand & Tone”.

  3. Scrivete le istruzioni (template a destra).

  4. Caricate i documenti nella knowledge base.

  5. Piano Team: decidete se condividerlo. ⚠ da verificare

Template di istruzioni 
Lavoriamo per UX Boutique, agenzia di UX
e design digitale. Lingua: italiano.
Tono diretto e concreto, niente
superlativi vuoti. Ogni testo per clienti
indica un beneficio misurabile.
Non citare clienti senza approvazione.
Quando non sei sicuro di un fatto,
dichiaralo. Usa il glossario caricato.
Cosa caricare
  • Sì: guida al tono, testi approvati, glossario, offerta ufficiale.
  • No: bozze, duplicati, dati personali non necessari.
  • Testo selezionabile, non scansioni.
Test del Project

Chiedete in una nuova chat dentro il Project: “Scrivi un’intro di 60 parole per la pagina servizi.” Se rispetta tono e glossario senza ripeterli, funziona. Confrontate con una chat fuori dal Project.

Modulo 4

Artifacts, ricerca web e analisi di file

Obiettivo: documenti modificabili, informazioni recenti verificate, analisi di file affidabili.

Artifact

  1. Chiedete il formato: “Crea un documento Artifact con…”.

  2. Modificate per sezione: “Nella sezione Metodo, riduci a tre punti.”

  3. Esportate quando è pronto.

Ricerca web

  1. Domanda in una frase, con periodo e pubblico.

  2. “Indica fonte e data per ogni affermazione.”

  3. Aprite le fonti delle affermazioni che userete.

Analisi di file
  • PDF: “Estrai le date di scadenza dei contratti.”
  • CSV: “Costo per lead per canale, segnala gli anomali.”
  • Screenshot: “Problemi di contrasto e accessibilità.”
  • Verificate a mano un valore su dieci.

Errori comuni: chiedere “migliora tutto” su un Artifact; fidarsi di un numero senza ricalcolarlo; caricare una scansione illeggibile.

Modulo 4b

Lavorare per file, poi l’artefatto

Obiettivo: preparare i contenuti in file .md nel repository, modificarli per parti e produrre l’artefatto visivo solo alla fine.

Su artefatto

Ogni modifica ripubblica la pagina intera. Il contenuto ripassa ogni volta per la chat e per la pubblicazione.

Su file

Il contenuto vive nel repository. Si modifica per sezioni, si verifica con Git, diventa artefatto solo quando è pronto. Più economico in token nei documenti lunghi; il vantaggio è pratico, non misurato.

FaseStrumentoPerché
Bozza e strutturaFile .mdVeloce da modificare, tracciato in Git
Revisione per sezioniFile .mdModifiche piccole e verificabili
Versione per il teamArtefatto o presentazioneLeggibile e condivisibile
Versione finaleExport HTML, PDF, PPTXPronta per il cliente

  1. Una cartella contenuti/progetto/ con un file per sezione e un indice.md.

  2. “Modifica solo 02-servizi.md: riduci a tre punti.” Poi git diff e un commit per sezione approvata.

  3. Generate l’artefatto o la presentazione dai file approvati.

Modulo 5 · Skills

Una Skill è un metodo scritto una volta

Prerequisiti: un processo ripetuto con un output che si può giudicare. Skills abilitate dall’admin del piano Team (confermato).

PromptSkill
QuandoUna voltaOgni volta che il compito si ripete
Dove viveNella chatIn una cartella con SKILL.md
Chi la usaChi la scriveChi ha la Skill disponibile, anche il team
Come si attivaSi scriveClaude la sceglie dalla descrizione
Struttura della cartella 
tono-ux-boutique/
├── SKILL.md
└── esempi/
    ├── post-buono.md
    └── post-da-evitare.md
Regole
  • Nome della cartella uguale al campo name, minuscolo con trattini.
  • SKILL.md obbligatorio, con frontmatter YAML: name e description.
  • Cartelle opzionali: scripts/, references/, assets/.

Modulo 5 · Skills

Il file SKILL.md

---
name: tono-ux-boutique
description: Scrive o revisiona testi per
  UX Boutique secondo il tono di voce del
  brand. Usala quando l'utente chiede copy,
  post, claim, intro o revisione di testi
  per clienti o per il sito.
---

# Tono di voce UX Boutique

## Quando usarla
Testi per clienti, post, pagine del sito.
Non usarla per documenti interni o codice.

## Procedura
1. Se mancano, chiedi pubblico, obiettivo
   e lunghezza.
2. Scrivi in italiano, tono diretto.
3. Ogni affermazione ha un beneficio
   misurabile, o va marcata da verificare.
4. Applica il glossario.
5. Rileggi rispetto ai criteri.

## Criteri di qualità
- Nessun superlativo vuoto.
- Una sola call to action.
- Frasi sotto le 25 parole.

## Formato di output
Testo finale, poi "Da verificare: ..."
La descrizione decide l’attivazione

Claude legge la descrizione per scegliere se usare la Skill. Scrivetela con le parole che userebbe chi chiede il lavoro.

Debole: “Aiuta con i testi.”

Efficace: “Scrive o revisiona post, claim e pagine per clienti UX Boutique. Usala quando l’utente chiede testi commerciali.”

Istruzioni
  • Passi numerati, nell’ordine di esecuzione.
  • Frasi precise: “Se il pubblico manca, chiedilo.”
  • Un esempio buono e uno da evitare.

Modulo 5 · Skills

Installare una Skill

Su claude.ai

  1. Preparate la cartella con SKILL.md.

  2. Comprimetela in .zip. La cartella deve essere la radice dell’archivio.

  3. Impostazioni → sezione Skills → caricate lo zip. ⚠ da verificare Le fonti indicano percorsi diversi, ad esempio “Customize → Skills” o “Settings → Capabilities → Skills”.

  4. Verificate che sia attiva e visibile per il vostro account.

In Claude Code

  1. Create .claude/skills/tono-ux-boutique/SKILL.md nel repository.

  2. Fate commit: la Skill è condivisa con chi lavora sul repository.

  3. Per una Skill personale, usate la cartella dell’utente. ⚠ da verificare

Come si usa
  • Chiedete un compito che la Skill copre: Claude la sceglie e segue i passi.
  • Per forzarla: “Usa la Skill tono-ux-boutique per questo testo.”
  • Per controllare: “Quali Skill hai per questo compito?”

Modulo 7

MCP e plugin

MCP

Model Context Protocol: lo standard con cui uno strumento espone le sue funzioni a Claude. Funziona come una presa USB: niente adattatori su misura.

Plugin

Un pacchetto che combina Skill, connettori e impostazioni per un ambito preciso, ad esempio project management.

Come si imposta in Claude Code 
claude mcp add nome-server -- comando-del-server
claude mcp list

⚠ da verificare la sintassi nella documentazione aggiornata. Per Drive, Figma e Miro usate i connettori del modulo 6.

  1. Verificate se esiste un server ufficiale.

  2. Installatelo in un progetto di prova e chiedete solo letture.

  3. Abilitate le scritture solo dopo, con revisione di ogni azione proposta.

Modulo 8 · Claude Design

Cos’è Claude Design e cosa produce

Obiettivo: produrre un prototipo, una presentazione o un one-pager da un brief, con contesto di brand, revisioni controllate ed export verificato.

Cosa produce
  • Prototipi: pagine o flussi navigabili.
  • Slide: da argomento, pubblico e numero di slide.
  • One-pager: sintesi o proposte su una pagina.
  • Landing page: campagne o prodotti.
Cosa non produce
  • Fotografie e illustrazioni originali.
  • Video.

Genera strutture, testi e stili da rivedere e modificare. Non è un generatore di immagini.

Prerequisiti
  • Accesso a Claude Design: presentato come anteprima di ricerca ad aprile 2026, l’accesso può dipendere dal piano. ⚠ da verificare
  • Un brief con pubblico, obiettivo e formato.
  • Brand kit o design system: colori HEX, font, logo, componenti.

Modulo 8 · Claude Design · Come si imposta

Prima di generare: accesso, brand, brief

  1. Accesso

    Aprite Claude Design dal vostro account. Se non lo vedete, verificate il piano con l’admin. ⚠ da verificare il punto di accesso

  2. Contesto del brand, una volta sola

    Un documento con palette in HEX, font e pesi, logo vettoriale o PNG trasparente, tono di voce con tre aggettivi, un testo approvato e i termini da evitare. Caricatelo nel Project del brand e, se possibile, collegatelo a Claude Design. ⚠ da verificare

  3. Verifica del contesto

    Descrivi il brand che stai usando:
colori, font, tono.

    Se la risposta non corrisponde al documento, correggete il contesto prima di andare avanti.

  4. Brief

    Formato (prototipo, slide, one-pager, landing), pubblico e obiettivo, sezioni in ordine con il loro messaggio, uno screenshot di riferimento con una frase su cosa vi piace, vincoli come “mobile first”.

Modulo 8 · Claude Design · Come si usa

Dal brief al prototipo, un passo per volta

  1. Struttura prima dello stile

    Proponi tre strutture diverse. Per ciascuna:
sezioni in ordine e contenuto. Non applicare
ancora colori né font.

    Se struttura e stile arrivano insieme, non capite quale parte non funziona.

  2. Prototipo

    Procedi con la struttura 2. Applica il brand
del contesto. Versione mobile first.

  3. Revisioni singole

    Il titolo dell'hero è generico. Proponi tre
alternative con un numero concreto. Applica
la prima; non cambiare altro.

    Una modifica per messaggio, sempre con il perché.

Modulo 8 · Claude Design

Verificare, poi esportare

Checklist prima dell’export
  • Contenuti e numeri approvati e verificati
  • Colori e font uguali al brand kit
  • Layout corretto su mobile
  • Una sola call to action

Esportate solo dopo la checklist. Un export è più difficile da correggere della bozza.

Opzioni riportate da fonti di terze parti: .zip, PDF, PPTX, HTML autonomo, invio a Canva, passaggio a Claude Code. Export come immagine ed export in formato Figma non risultano confermati. ⚠ da verificare

Modulo 10

Claude Code: un agente che lavora sui file

Legge, modifica e crea file ed esegue comandi, con la vostra supervisione. Non è solo per sviluppatori: chi lavora su documenti in cartelle ne trae lo stesso vantaggio.

Installazione e primo avvio

App desktop oppure terminale, seguendo la documentazione ufficiale. ⚠ da verificare il comando

cd percorso/della/cartella
git init      # solo se non è un repository
claude        # avvia Claude Code

Prima richiesta: “Elenca i file di questa cartella e spiega cosa contengono.”

Git in breve
  • Commit: una versione salvata con una descrizione.
  • Branch: una linea di lavoro separata.
  • Push: invio delle modifiche al repository remoto.
  • Pull request: richiesta di unire un branch, con revisione.
git status
git add percorso/del/file
git commit -m "Descrizione chiara"
git log --oneline -5

Errori comuni: lavorare senza Git, commit enormi con modifiche non correlate, credenziali nei file del repository.

Modulo 11

Plan mode, permessi, subagent

Plan mode

Claude propone un piano e aspetta l’approvazione prima di modificare i file.

Attivazione: Shift+Tab, il comando /plan o il flag di avvio. ⚠ da verificare

Permessi

Claude Code chiede conferma per modificare file ed eseguire comandi. Concedete per una singola azione o per la sessione, mai “approva tutto” alla cieca.

Subagent

Agenti secondari per un sotto-compito. Tra quelli integrati ci sono Explore e Plan; secondo la documentazione ufficiale non caricano CLAUDE.md, per restare veloci.

Richiesta in plan mode 
Aggiungi alla landing una sezione "Caso studio" con tre numeri
da design/tokens.json. Non introdurre colori fuori dai token.
Mostra il piano con i file che tocchi.

  1. Leggete il piano. Se un passo non è chiaro, chiedete di spiegarlo.

  2. Approvate, verificate il risultato, fate commit.

Modulo 12

Attività programmate

Obiettivo: automatizzare un compito ripetuto con un controllo umano sull’output. Prerequisiti: una Skill o un Project già testati.

Come si imposta

  1. Scrivete il compito come per un collega: input, passi, output, destinazione.

  2. Fatelo una volta a mano, con esito positivo.

  3. Programmate l’intervallo. ⚠ da verificare dove

  4. Definite dove finisce l’output.

Esempio: report settimanale

  1. Note della settimana da Drive, riassunte con la Skill “status report”.

  2. Programmazione: ogni lunedì mattina.

  3. Output in un documento condiviso, con la riga “Da verificare”.
